# 日志与诊断

## 用户入口

设置页的“运行诊断”提供：

- **打开日志目录**：在资源管理器打开 `%LOCALAPPDATA%\lol-stats\logs`。
- **导出诊断包**：先提交待发送的前端日志，再等待后台日志队列写入，生成 ZIP 并在资源管理器中选中。
- **详细日志（10 分钟）**：默认关闭，不持久化；打开后临时增加 DEBUG 信息，到期自动停止记录。兼容开发环境变量 `LOL_STATS_VERBOSE_LOG=1`，同样限时 10 分钟。

反馈流程：开启详细日志，复现问题，再点击导出，将 ZIP 发送给开发者。软件不会自动上传日志。

## ARAMKit 连接诊断

“设置 -> ARAMKit 胜率数据 -> 本地代理”还提供“启用 WTLS”和“超时时间”：

- WTLS 指 Windows 系统 TLS（Schannel），默认关闭。超时默认 20 秒，开启 WTLS 后可编辑为 1 到 120 秒的整数；设置通过原有“保存”按钮持久化。关闭 WTLS 不清除已填写的超时时间。
- 开启后，正式 ARAMKit 请求始终先用 Rustls，网络失败后改用 WTLS，同一 URL 的一次请求链最多为 `Rustls -> WTLS -> WTLS`，即首次加两次重试。两者的建连和整个请求（含正文下载）使用相同超时，重试不擅自延长。
- 关闭时只使用 Rustls，不进行这组即时兼容重试。这里限制的是一次 HTTP 请求链；识别线程原有的数据加载失败退避仍保留，已成功的缓存不重新下载。
- 超时、连接中断、正文断流和部分瞬时 HTTP 错误可触发重试；普通 4xx、带 `Retry-After` 的响应及 JSON 解析错误不进行这组立即重试。两次重试前分别等待 500 / 1000 ms。
- 两种后端始终使用同一份代理配置快照，不回退直连，不关闭证书验证。原生 TLS 客户端只在首次失败后按需创建；战绩、LCU、软件更新和其他请求不使用这个开关。

“设置 -> ARAMKit 胜率数据 -> 测试连接”使用当前填写的代理配置，不必先保存。

- 手动串行检查主站数据版本、全英雄胜率总表，以及薇恩（英雄 ID `67`）的海克斯 JSON；不仅检查 HTTP 成功，还校验 JSON 中的有效海克斯数据。
- 对照当前 Rustls 和 Windows 系统 TLS（Schannel）。当前构建没有启用 HTTP/2，已经使用 HTTP/1.1，因此不重复测试等价的“强制 HTTP/1.1”组合。
- 各组使用相同代理、相同 URL、HTTP/1.1 和超时设置；先从本轮主站请求取得有效版本，再固定该版本进行数据站对照。即使某一组主站失败，只要另一组取得版本，仍继续检查前一组的数据站访问。
- 两组均使用当前填写的超时（默认 20 秒）；瞬时网络错误最多以相同超时重试两次，不再使用旧的 6 / 12 秒或延长超时方案。为分别观察 TLS 后端，诊断中的重试保持原后端，不套用正式请求的自动切换。请求之间间隔 250 ms，整轮最多 180 秒，到期保留已有结果。
- 每次请求独立建连，不使用或修改生产数据缓存，不保存表单配置，不关闭证书验证，也不自动切换正式请求的 TLS 后端。系统 TLS 使用 Windows 证书库，与 Rustls 的 webpki 根证书有区别，对照成功不直接证明某个库有 bug。
- 结果记录软件 / 系统版本、时间、代理入口、测试 URL、HTTP 状态与版本、响应头和正文耗时、已读取字节、失败阶段和完整错误链；成功时记录英雄数量、薇恩基础胜率、有效海克斯数量及少量海克斯 ID / 胜率样例，不复制整个 JSON。
- “复制结果”位于“测试连接”左侧。无论测试成功、部分成功还是失败，都可以直接复制本轮多行报告。报告只保留在本次运行内，包含测试时的配置快照；下一次测试开始时替换。
- 报告复用日志脱敏规则，保留换行；逐步结果也写入应用日志。不包含代理订阅、认证令牌、战绩、截图或整份代理配置。代理入口不等于实际出口节点，节点信息仍以代理软件记录为准。

页面区分“Rustls 通过”和“只有系统 TLS 对照通过”，报告会记录 WTLS 开关状态。重试成功也保留最初的失败记录，避免将偶发成功当成确定结论；诊断不会自动保存当前表单。

## 文件与保留

- 当前日志：`%LOCALAPPDATA%\lol-stats\logs\app.log`。
- 归档：同目录下 `app.log.YYYYMMDDTHHMMSS`，同秒轮转会追加序号。
- 诊断包：`%LOCALAPPDATA%\lol-stats\diagnostics\lol-stats-diagnostics.zip`，下次导出覆盖该文件，避免持续累积。
- 每次启动重新归档当前日志；跨日或下一条日志将超过 5 MiB 时轮转，不截断单条日志。
- 最多 9 个归档加当前文件，总量不超过 50 MiB；启动和轮转时淘汰超过 7 天的归档。文件数量先达到上限时，会提前淘汰较早日志，不保证完整保留 7 天。
- `%LOCALAPPDATA%` 不可用时，回退到系统临时目录下的 `lol-stats`。
- 旧的 `hex-winrate.log`、`quick-bench-swap.log` 不再追加，也不纳入新诊断包；已有旧文件未主动删除。

## 记录内容

默认记录 INFO / WARN / ERROR：

- 应用版本、进程号、启动和正常退出。
- 游戏阶段变化、窗口尺寸保存和恢复、识别开关及截图/检测方案设置。
- ARAMKit、全服基线、本机接口、截图与 OCR 的关键状态和异常。
- 已确认的海克斯 OCR 原文、匹配结果、统计命中情况与收益率。
- Vue 异常、JavaScript 异常、未处理的 Promise 错误及错误提示。
- 前端调用 Rust 命令的失败信息、关键查询开始/结束，以及耗时达到 2 秒的调用。耗时包括 IPC 往返与后端处理，不等同于纯网络耗时，也不包含结果返回后的页面渲染。
- Rust panic 的文本和源码位置。原生 DLL 访问违规、进程被强杀等并不保证被 panic hook 捕获。

详细日志额外包含 OCR 裁剪和候选原文、选人布局快照、页面切换及鼠标诊断信息。不输出截图、请求参数、完整战绩 JSON 或 Vue 状态快照，不逐帧记录截图成功。

前后两条调用日志可以通过 `request_id` 关联；该 ID 是前端为本次调用生成的流水号，不是玩家 ID。不同并发请求不会共享同一个全局请求 ID。

## 性能与隐私

- Rust 使用 `tracing` / `tracing-subscriber`，通过 `tracing-appender` 的有界非阻塞队列送到后台写线程；文件轮转使用 `file-rotate`。
- 后台队列最多 512 条，满时丢弃新日志，不阻塞截图和业务线程；丢弃计数显示在设置页并写入诊断环境信息。
- 前端最多缓存 100 条，每批 32 条，仅在有日志时延迟批量提交；队列不进入 Vue 响应式系统。优先丢弃普通和详细日志，保留错误；不常驻轮询日志文件。
- 相同 WARN / ERROR 在 30 秒内合并，保留首次错误并汇总重复次数。比较时忽略流水号和耗时，状态切换和 OCR 确认结果不因此被隐藏。
- DEBUG 关闭时，不构造 OCR 调试文本。详细日志使用动态过滤，到期后无需重启即可停止。
- 写盘前过滤常见认证字段、Basic/Bearer 凭据、URL 用户名/密码及查询参数、常见玩家标识和本机用户目录。
- 不主动记录账号查询参数、聊天签名或完整配置。任意错误文本和误识别的 OCR 文本仍可能含未识别出的个人信息，公开发帖前应检查诊断包。
- 诊断包只含当前日志与归档，以及版本、系统版本、架构、运行时长、日志队列丢弃计数和最近写盘错误；不包含 SQLite、游戏截图或认证缓存。
- 导出压缩在后台进行，读取已打开文件的固定长度快照，不在压缩期间持有日志写入锁。正常退出和 panic 时尽力等待队列写入，强制结束、断电或队列拥塞时仍可能丢失少量日志。

## 海克斯名称显示

“设置 -> 局内识别 -> 显示海克斯识别结果”默认关闭，并独立保存在本机。

关闭时只隐藏叠层上方的海克斯名称，收益率以及“选取率过低”提示仍正常显示；开启后恢复名称。切换不清除定位缓存，不重新请求 ARAMKit，不改变识别频率，也不影响日志中记录的 OCR 结果。

## 代码入口

- `src-tauri/src/services/runtime_log.rs`：日志初始化、后台输出、脱敏、归档、详细开关和诊断包。
- `src-tauri/src/lib.rs`：在 Tauri 构建前初始化，在退出事件中等待日志写入。
- `src/logging.ts`：前端异常、命令耗时与批量提交。
- `src/main.ts`：注册 Vue 和全局异常处理。
- `src/App.vue`：日志设置与海克斯名称显示开关。
- `src-tauri/src/services/hex_winrate/diagnostics.rs`：ARAMKit 手动连接对照、薇恩海克斯校验与可复制报告。
