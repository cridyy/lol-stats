# 全服基准

全服数据的目的不是把所有人变成同一套英雄模板，而是回答两个问题：

1. 这个英雄在同样的海克斯大乱斗环境下，通常能完成多少工作？
2. 这局玩家的工作量，是低于、接近，还是明显高于自己所玩英雄的常态？

当前快照只保存英雄均值，没有中位数、百分位或原始玩家分布。因此“超过全服 140%”的含义是“达到该英雄平均值的 1.4 倍”，不能解读成“超过了全服 140% 的玩家”。

## 数据位置和生命周期

运行时数据位于：

```text
%LOCALAPPDATA%\lol-stats\global-baselines\current.json
```

相关文件：

| 文件 | 作用 |
| --- | --- |
| `current.json` | 当前完整英雄基准快照 |
| `manifest.json` | 数据版本、大小和 SHA-256 校验信息 |
| `check-state.json` | 每日更新检查状态 |

应用启动后会异步检查远端清单。数据缺失、损坏、版本不支持、英雄数量不完整或校验失败时，不阻塞主界面；评分继续使用没有全服项的基础公式。

快照必须是完整数据集，且每个英雄的游戏时长和核心数值合法。当前数据源是海克斯大乱斗，应用只在队列 `2400`，或模式名为 `KIWI` / `STRAWBERRY` 的对局中使用这套基准。

## 21 项数据

每个英雄记录一组平均值。旧快照可能缺少扩展字段，但当前目标 schema 是 21 项：

| 分组 | 指标 |
| --- | --- |
| 战绩 | KDA、击杀、死亡、助攻、参团率、多杀 |
| 伤害 | 对英雄伤害、物理伤害、魔法伤害、真实伤害、伤害占比、推塔伤害 |
| 生存与功能 | 承受伤害、自我减免、队友治疗、队友护盾、控制时长 |
| 资源与时间 | 金币、补刀、游戏时长、伤害经济转化率 |

字段名对应：

```text
averageKda
averageKills / averageDeaths / averageAssists
participationRatePercent / multikills
damageToChampions / physicalDamageToChampions / magicDamageToChampions / trueDamageToChampions
damageSharePercent / turretDamage
damageTaken / selfMitigatedDamage
allyHealing / allyShielding / crowdControlDurationSeconds
goldEarned / cs / gameDurationSeconds
damageGoldConversionRatePercent
```

英雄记录还保留 ARAMKit 的 `relativeToGlobalAveragePercent`（“较平均”百分比）以及来源日期。百分比指标是百分点差，不是相对倍率；当前标记为百分点指标的字段是参团率、伤害占比和伤害经济转化率。

## `globalAverages` 的反算

根节点 `globalAverages` 是为了做全服总览、六边形图和后续分析而提供的全服人均估计，不直接替代某个英雄的基准。

对于相对百分比字段，先对每个英雄反算：

```text
候选全服均值 = 英雄均值 / (1 + 较平均百分比 / 100)
```

对于百分点字段，反算为：

```text
候选全服均值 = 英雄均值 - 较平均百分点差
```

然后对每项所有有效英雄候选值取中位数：

```text
globalAverages[指标] = median(所有有效英雄的候选全服均值)
```

这就是 `globalAverageEstimation.method = medianOfReverseCalculatedChampionValues` 的含义。`candidateCounts`、`excludedCandidateCounts` 和 `incompleteMetrics` 用于审计哪些指标有多少有效候选值。

例如当前快照的量级包括：全服平均 KDA `3.9`、对英雄伤害 `42177`、承受伤害 `46272`、自我减免 `47210`、队友治疗 `500`、队友护盾 `473`、控制时长 `34.1` 秒、游戏时长 `1040` 秒。具体数值随数据集版本更新，不应在业务代码中写死。

## 正式评分：只改辅助

全服数据正式进入百分制的范围非常窄：

- 最终定位为辅助。
- 对局属于海克斯大乱斗。
- 当前英雄存在有效基准。
- 本局至少有一个可观测、可比较的指标。

输出、法师、战士和前排完全沿用基础评分，不因全服文件加载状态改变。这样可以先观察“辅助引入全服水平”对结果的影响，不把全服噪声扩散到整个系统。

辅助全服分不是额外加分，而是固定的一项 `0-25` 分：

| 来源 | 被替换的旧小项上限 |
| --- | ---: |
| 参团 | 5 |
| 人头质量 | 7 |
| 有效伤害 | 13 |
| 合计 | 25 |

实际替换的是本局旧公式在这三项已经拿到的分，不是无条件从基础分扣掉 `25`：

```text
正式辅助分 = 基础分
           - 本局旧参团分
           - 本局旧人头质量分
           - 本局旧有效伤害分
           + 全服分
```

因此全服基准不可用时，辅助直接回退基础分；可用时，正式分、评价、画像和接口中的 `score.value` 都使用替换后的结果。

## 同英雄、同时间比较

累计伤害、承伤、治疗等会随着对局变长自然增加，所以先换算为分均值：

```text
本局分均表现 = 本局数值 / 本局分钟数
英雄全服原始分均 = 英雄全服平均数值 / 英雄全服平均游戏分钟数
折算后的全服分均 = 英雄全服原始分均 × 时长折算倍率
表现倍数 = 本局分均表现 / 折算后的全服分均
```

### 时长折算

玩家的短局不应因为没有打满装备而直接输给一局 16 分钟样本；20 分钟以上则允许略高的合理预期：

| 本局时长 | 全服分均折算倍率 |
| --- | ---: |
| `<= 8` 分钟 | `0.60` |
| `8-16` 分钟 | `0.60` 线性增加到 `1.00` |
| `16-20` 分钟 | `1.00` 线性增加到 `1.10` |
| `>= 20` 分钟 | `1.10` |

例如全服平均分均治疗为 `1000`：8 分钟局按 `600` 比较，12 分钟按 `800`，16 分钟按 `1000`，18 分钟按 `1050`，20 分钟及以上按 `1100`。折算只改变比较基准，不改变辅助全服分的 `25` 分容量。

## 辅助职责分权

辅助不再使用一套对所有英雄相同的治疗/护盾权重。先把可比较指标分为四条路线：

1. 保护：队友治疗、队友护盾。
2. 耐久：承受伤害、自我减免。
3. 输出：对英雄伤害。
4. 控制：控制时长。

同一路线内部按该英雄自己的全服均值构成分权：

```text
治疗权重 : 护盾权重 = 该英雄全服治疗均值 : 该英雄全服护盾均值
承伤权重 : 减免权重 = 该英雄全服承伤均值 : 该英雄全服减免均值
```

所以星妈这类治疗型英雄不会因为一个很小的护盾均值而被错误地按护盾评分；护盾型英雄也不会被强行要求完成治疗工作。缺失字段保持中性，不把权重偷偷转给别的指标。

保护和耐久合并为基础辅助工作。输出与控制只有在自己的综合表现高于基础辅助工作时才借权，二者合计最多借走 `35%` 的全服指标权重；其余权重仍归保护和耐久。

```text
基础辅助工作 = 保护路线与耐久路线按路线表现加权后的结果
输出优势 = 输出路线表现 - 基础辅助工作
控制优势 = 控制路线表现 - 基础辅助工作

只有优势 > 0 才允许借权
输出/控制借权合计 <= 35%
```

这条规则允许“辅助装或肉装带来的团队收益”被看见，同时防止辅助只刷自己的伤害就完全改写职责评价。

## 英雄池补充基准

如果本局装备让一个原生输出英雄进入辅助分支，而该英雄自身没有治疗、护盾或控制的有效全服均值，系统不会凭空给它制造分母：

1. 只收集原生辅助英雄的全服分均值。
2. 每项在这些英雄之间取中位数，形成辅助英雄池基准。
3. 只比较本局超过该英雄自身常态的新增分均工作量。

```text
新增工作量 = max(0, 本局分均表现 - 本英雄折算后的常态)
新增工作完成度 = clamp(新增工作量 / 辅助英雄池折算基准, 0, 1.5)
```

没有新增工作量就不加分，也不会因为英雄原本没有治疗或护盾能力而扣分。这个补充只在最终定位已经是辅助、且发生了“装备定位和英雄原生定位变化”时使用。

## 六项正式比较指标

正式辅助全服分当前从以下六项中动态取权：

- 对英雄伤害。
- 承受伤害。
- 自我减免。
- 队友治疗。
- 队友护盾。
- 控制时长。

某项全服均值低于噪声门槛时不参与：伤害/承伤/减免至少 `1000`，治疗/护盾至少 `100`，控制时长至少 `1` 秒。该项既不加分也不扣分，避免接近零的分母制造夸张倍率。

综合表现倍数按有效指标权重加权，缺失指标不纳入权重：

```text
综合表现 = Σ(指标权重 × 指标表现倍数)
```

全服分曲线为：

```text
综合表现 <= 1：全服分 = 15 × 综合表现
综合表现 > 1：全服分 = 15 + 10 × (综合表现 - 1) / 0.5
```

曲线在 `0.5 / 1.0 / 1.5` 倍时分别约为 `7.5 / 15 / 25` 分；超过 `1.5` 倍封顶。达到英雄全服平均水平就是全服项的及格线 `15/25`，不是把 25 分全部白送。

## 全服数据与称号

称号系统可以读取比正式评分更多的扩展字段（KDA、击杀、参团率、伤害占比、金币、补刀、伤害经济转化率等），但这不会改变“只有辅助正式评分引入全服数据”的边界。

动态“国服最强某英雄”称号使用当前英雄自身基准，要求本局评分和多项英雄倍率同时达到高门槛，详见[称号系统](title-system.md)。因此一个辅助即使被正式评分按辅助分支处理，国服证据仍然比较该英雄自身，不会被辅助英雄池替换。

## 当前边界

- 只有均值，没有中位数和百分位：适合做相对强弱，不适合宣称精确排名。
- 不同模式不能混用当前快照。
- 数据集更新可能改变同一局的全服倍率和称号，但不会改变非辅助基础评分公式。
- 全服分用于正式辅助评分、辅助画像和称号证据；六边形图目前可以使用 `globalAverages` 做参考，不能把它当成玩家排名。
