# 评分与称号校准

校准的目标不是把普通玩家都夸成高手，也不是让神话称号永远没人见过，而是让分数和称号在真实样本中“有梯度、有机会、能解释”。

## 分数语义

当前分数的产品语义是：

| 分数 | 用户理解 |
| ---: | --- |
| `90+` | 明显顶尖，神话/国服称号的候选区间 |
| `80-89` | 厉害，败方高光和职责高光的主要区间 |
| `70-79` | 正常偏好，普通人打得不错但还不是碾压 |
| `60-69` | 小正常人，发挥有亮点但存在明显短板 |
| `<60` | 基本拉跨，进入调侃或低表现区间 |

界面沿用的评价文本是：`通天代 / 小代 / 小有实力 / 普通人 / 小坑比 / 大坑比`。文本是展示层，校准时优先看分数分布和实际命中行为。

## 三组海克斯大乱斗样本

历史校准使用三类账号，各取目标 `100` 局海克斯大乱斗：

| 样本 | 账号角色 | 评分均值（记录量级） | 中位数（记录量级） |
| --- | --- | ---: | ---: |
| 普通玩家 | 普通人水平 | 约 `65.3` | 约 `64.5` |
| 普通偏上 | 普通人稍好 | 约 `71.2` | 约 `77.5` |
| 高水平玩家 | 明显强于普通人 | 约 `89.4` | 约 `94` |

样本文件位于开发数据目录 `lol-stats-data/title-samples/`，不随应用安装包发布。分数会随全服快照、同局完整度和代码版本变化，以上数字是某次校准的参考量级，不是固定测试快照。

## 为什么高光称号要高门槛

普通玩家的 `70` 分是“正常偏好”，不能因为刚过 `65` 就获得“女武神”或“渡劫失败”。当前高光称号的最低分数分别是：

- 悲情英雄：`80`。
- 女武神：`85`。
- 渡劫失败：`82`。
- 莫欺少年穷：`80`。
- 国服最强某英雄：`90`，并且还要有英雄全服倍率证据；输出路线的修正伤转还必须达到 `1.40`。

这些称号还需要队内名次、队友均分、对手均分、输出/承伤等相对证据；只看个人分数不足以命中。

## 普通玩家可见性原则

称号池是随机展示，但判定本身保留全部命中结果。校准遵循以下原则：

1. 普通玩家在 `60-79` 分的正常局仍能命中评分称号或职责特征称号；“一般人机”“小泯一把”“发癫了？”“自转的陀螺”“泉水指挥官”只接受低于 `60` 分的对局。
2. 普通玩家偶尔打出 `80+` 时，可以命中职责高光或败方高光；不要求全场第一。
3. `队友平均分 <=45`、个人分数 `<=20` 只用于极端调侃或残缺/挂机证据，不作为常规夸奖条件。
4. “少冰七分糖”必须包含明确弱项，表示玩得唐，不表示稳定发挥；“一般人机”“小泯一把”“发癫了？”“自转的陀螺”和“泉水指挥官”也不能覆盖 `60+` 的正常局。
5. 国服称号必须稀有，但所有英雄都有机会；输出路线还必须有至少 `1.40` 的修正伤转，不是只给少数热门英雄写死名称。

## 校准时重点观察的量

不要只看称号总数，应同时看：

| 观察项 | 期望现象 |
| --- | --- |
| 各分数段占比 | 普通、普通偏上、高水平之间有明显梯度 |
| 正常称号命中 | 普通玩家不是 100 局全空，也不是每局都同一个称号 |
| 高光称号命中 | `80+` 局明显增加，`60-79` 局不会大量误触发 |
| 调侃称号命中 | 与低分、弱项和错位表现相关，不被普通局淹没 |
| 败方高光 | 个人高分且有相对证据才出现，不是“输了就有” |
| 国服称号命中 | 90+ 且至少两项英雄倍率很高；普通玩家偶尔可见，不能泛滥 |
| 缺失数据 | 没有完整队伍时，依赖队友比较的称号安静失效 |

## 推荐校准流程

### 取样

使用本机接口，按模式精确取样：

```powershell
$base = 'http://127.0.0.1:17390/v1/player-history'
Invoke-RestMethod "$base?gameName=游戏ID&tagLine=编号&server=TENCENT_HN1&mode=hex-aram&count=100"
```

接口会继续扫描历史，直到凑够目标模式场数或确认没有更多有效对局。记录响应中的：

- `globalBaseline.datasetVersion`。
- `coverage.returnedGames`、`coverage.scannedGames`。
- `summary.score` 和 `profile`。
- 每局 `games[].score.value`、`games[].score.titles`、`games[].score.titleDetails`。

### 对比前后版本

同一账号、同一模式、同一全服快照下，比较：

```text
分数均值 / 中位数 / 标准差
各分数段数量
每个称号的命中次数
没有完整队伍时的依赖称号数量
国服称号的命中次数和证据倍率
```

如果只改变称号条件，分数分布应保持不变；如果改变评分公式，则应单独记录分数变化，避免把评分变化误认为称号变化。

### 调参顺序

1. 先确认分数段符合 `90+ 顶尖、80+ 厉害、70-79 正常、60-69 小正常、<60 拉跨` 的语义。
2. 再调整高光称号的最低分和相对比较门槛。
3. 最后调整普通、职责和调侃称号，优先用普通样本检查可见性。
4. 国服称号单独校准，不用降低普通称号门槛来“增加新鲜感”。

## 现有实现的安全线

- 称号不改变正式评分，也不进入长期统计。
- 原评分 tag 与娱乐称号合并进入 `titles` 全集；随机只改变 `displayTitle`，不会删除任何命中结果。
- 全服快照只有均值，没有百分位；国服理由只能写“英雄均值的倍数”，不能写“超过全服多少玩家”。
- 全服辅助分只影响辅助；其他定位评分前后应严格相等。
- 败方推掉两座塔时不启用碾压校准；一座塔的败方首塔若在 `75%` 进度才发生，胜方 KDA 借权从零开始；败方零塔即使超过 `16` 分钟也可触发，但时长影响会继续衰减。败方自身永远不启用碾压 KDA，只保留其他碾压校准和失败抵抗保护。

## 自动检查

提交前运行：

```powershell
npm run check:frontend
npm run check:backend
npm run test:scoring
npm run test:backend
npm run build
git diff --check
```

其中 `scripts/verify-scoring.mjs` 至少覆盖：全服辅助分替换、输出定位不受全服分影响、败方首塔门槛、败方两塔排除、动态国服英雄称号和画像分数一致性。
