# 评分系统说明

本文档对应当前代码中的评分实现，主要来源：

- `src/scoring.ts`：单局百分制评分、单局标签、评分提示。
- `src/globalBaselines.ts`：全服基线的前端加载状态和英雄索引。
- `src/roleClassifier.ts`：根据英雄和装备判断玩家本局定位。
- `src/playerProfile.ts`：玩家画像、单英雄画像、综合标签。
- `src-tauri/src/services/global_baselines.rs`：全服基线快照的下载、校验和本地读取。

评分系统不是 Riot 官方评分，也不是固定按英雄模板评分。它的核心目标是给海克斯大乱斗、极地大乱斗一类团战模式提供一个“电子斗蛐蛐”视角下的可解释分数。

## 总体流程

1. 从对局数据中计算基础指标。
2. 根据英雄标签和出装判断本局定位。
3. 根据定位进入不同评分公式。
4. 得到 0-100 的单局得分。
5. 根据得分和关键指标生成单局评价标签。
6. 多局聚合后生成玩家画像、单英雄画像和画像标签。

所有百分比在公式中都按 `0-1` 的小数计算，例如 `25% = 0.25`。

## 全服均值正式评分（仅辅助）

界面和统计只保留一个正式得分，不再显示“原评分 | 全服评分”的双分形式。

最终评分分支为辅助且全服基准可用时，全服表现作为百分制中的固定 `25` 分项，直接替换原辅助公式中的同容量小项。这个正式得分用于战绩横条、具体战绩、评价标签、玩家画像、英雄统计、平均分、高光率、战犯率和其他多局统计。

输出、法师、战士和前排完全沿用原评分，不读取全服水平，也不改变任何评分小项。辅助遇到模式不适用、英雄基准缺失、基准文件不可用或本局数据无效时，也会回退原评分，界面不会显示空分。

是否属于辅助直接复用原评分已经得到的本局定位，不再另外创造一套英雄类型，也不会由全服侧重新判断。辅助正式分生成评价标签时使用正式得分，定位与原始对局指标仍沿用同一套定位和指标计算。

### 数据来源和适用范围

基准快照存放在：

```text
%LOCALAPPDATA%\lol-stats\global-baselines\current.json
```

当前快照是海克斯大乱斗数据，因此只对队列编号 `2400`，或游戏模式为 `KIWI`、`STRAWBERRY` 的对局启用。不能拿这套基准校准普通大乱斗、排位或其他模式。

每个英雄包含七项全服平均数据：

- 对英雄伤害。
- 承受伤害。
- 自我减免。
- 队友治疗。
- 队友护盾。
- 控制时长。
- 游戏时长。

游戏时长用于换算本局分均值，并用于折算同一时长下的全服分均基准，本身不单独加分或扣分。因为快照只有平均值，没有玩家中位数和百分位，所以当前只能表达“达到该英雄折算后全服基准的多少倍”，不能据此声称玩家超过了全服多少百分比的人。

### 仅适用于辅助分支

全服评分项只在原评分最终定位为辅助时启用。原评分中的以下分支不再引入任何全服数据：

- 输出：射手、刺客、纯刺客、功能输出和无法细分的输出定位。
- 法师：法师定位。
- 战士：战士、半肉战士和战士刺客定位。
- 前排：坦克定位。

辅助仍统一覆盖治疗型、护盾型和开团承伤型，不拆分辅助子类型。英雄标签和本局装备如何共同决定定位，仍完全由 `src/roleClassifier.ts` 负责。

### 固定分池及来源

辅助全服评分项满分为 `25` 分，从原辅助评分中等量让出：参团 `5` 分、人头质量 `7` 分、有效伤害 `13` 分。其他四个评分分支没有全服分池，也不让出任何原评分容量。

“让出”按旧小项本局实际完成度计算。例如辅助本局原先只在这三项拿到 `12` 分，就从原评分扣除这 `12` 分，而不是无条件扣除 `25` 分。正式分公式为：

```text
辅助正式评分 = 原评分 - 被替换旧小项的本局得分 + 全服评分项得分
```

### 同英雄分均比较

所有参与比较的数据先换算成分均值，避免长对局天然拥有更高累计数值：

```text
本局分均表现 = 本局数值 / 本局分钟数
全服原始分均表现 = 英雄全服平均数值 / 英雄全服平均分钟数
全服折算分均表现 = 全服原始分均表现 × 时长折算倍率
表现倍数 = 本局分均表现 / 全服折算分均表现
```

辅助各指标按本局动态权重合成为综合完成度。达到全服水平时拿 `15/25` 分，超过全服水平 `50%` 时拿满剩余分数：

```text
综合完成度 = 所有指标的“本局动态权重 × 表现倍数”之和

辅助分支，综合完成度不超过 100%：全服项得分 = 15 × 综合完成度
辅助分支，综合完成度超过 100%：全服项得分 = 15 + 10 × (综合完成度 - 100%) / 50%
```

因此：

- 辅助达到全服水平的 `50%`、`100%`、`150%` 时，分别得到 `7.5`、`15`、`25` 分。
- 低于全服水平不会产生负分，而是按完成比例连续获得及格分池中的分数。
- 超过全服水平 `50%` 后不再继续增加全服项得分。
- 中间区间连续变化，不存在刚过某个阈值就突然跳分的问题。

### 动态职责分配

全服侧只在辅助的六项指标间动态分权。治疗、护盾、承伤与减免共同表达基础辅助工作；伤害和控制只有优于基础辅助工作时才借权，二者合计最多借走 `35%`。

同一路线中的固有比例由该英雄自己的全服基准决定，而不是看本局哪个数字更高就临时偏向哪个数字。例如某英雄全服分均治疗与分均护盾为 `9:1`，本局保护路线中的治疗与护盾权重也保持 `9:1`。承受伤害与自我减免同样按该英雄全服两项基准的比例拆分。这样治疗型辅助不会因为一个很小的护盾基准而得到过高护盾权重。

### 全服分均时长折算

短局尚未形成完整装备，直接和约 16 分钟对局的全服分均数据比较会吃亏；长局装备成型后，合理预期又应略高。因此根据本局时长折算拿来比较的全服分均基准，而不是缩放最后算出的全服评分项：

```text
本局不超过 8 分钟：时长折算倍率 = 0.60
本局处于 8-16 分钟：时长折算倍率 = 0.60 + (本局分钟数 - 8) / 8 × 0.40
本局处于 16-20 分钟：时长折算倍率 = 1.00 + (本局分钟数 - 16) / 4 × 0.10
本局达到 20 分钟及以上：时长折算倍率 = 1.10
```

例如某辅助英雄全服原始分均治疗为 `1000`，8 分钟局用 `600` 作比较基准，12 分钟局用 `800`，16 分钟局用 `1000`，18 分钟局用 `1050`，20 分钟及以上用 `1100`。时长只改变比较基准，不改变辅助 `25` 分的固定分池。

同一个时长折算倍率会同时作用于本英雄全服分均基准和评分分支英雄池基准，伤害、承伤、减免、治疗、护盾与控制全部使用相同口径。

### 评分分支变化

仅当本局最终进入辅助分支时，系统才额外用“只有英雄标签、没有本局装备”的定位结果判断是否由其他分支转为辅助。发生变化时，悬浮提示显示“评分分支变化”。

本英雄全服基准达到噪声门槛的指标，仍直接与本英雄常态比较。只有发生评分分支变化，并且本英雄常态几乎没有某项新职责时，才启用新分支英雄池：

1. 只收集原生辅助英雄的全服分均平均值。
2. 对各英雄的全服分均平均值取中位数，得到辅助英雄池基准。这里是“多个英雄平均值之间的中位数”，不是玩家表现中位数。
3. 只计算本局超过该英雄折算常态的新增工作量；没有新增工作量就没有收益，也不会因为英雄原本不具备该能力而扣分。

```text
新增分均工作量 = max(0, 本局分均表现 - 本英雄折算后的分均常态)
新分支完成度 = clamp(新增分均工作量 / 新分支英雄池折算基准, 0, 1.5)
```

例如其他定位的英雄因辅助装最终进入辅助分支时，已有有效同英雄基准的能力直接与本英雄常态比较；没有有效同英雄基准的新辅助职责才用辅助英雄池衡量新增工作量。是否进入辅助分支完全服从原评分定位。

### 噪声门槛

某英雄不具备有意义的治疗、护盾或控制能力时，不应让接近零的全服均值制造夸张倍数。因此先使用以下全局平均总值门槛剔除噪声项：

- 对英雄伤害、承受伤害、自我减免：至少 `1000`。
- 队友治疗、队友护盾：至少 `100`。
- 控制时长：至少 `1` 秒。

剔除后，该项保持中性，不会制造夸张倍数。例如某个辅助英雄本来没有有效队友治疗基准时，不会因为接近零的分母得到异常高分。

### 缺失值处理

新加入的本局字段是“队友治疗”和“控制时长”。旧缓存没有这两个字段时，后端保留为缺失状态，而不是补成真实的零：

- 字段缺失：该项保持中性，不加分也不扣分，同时不把它的权重转给其他项。
- 字段存在且数值为零：视为本局真实零表现，正常参与校准。
- 英雄基准缺失：不生成全服项，原评分作为正式分。
- 基准文件缺失、损坏、版本不支持或英雄数量校验失败：不生成全服项，原评分作为正式分继续工作。

悬浮评分提示只显示一个正式总分。辅助成功启用全服评分时，全服相关内容只保留一行 `全服得分 X/25分`；不再展示被替换小项、综合完成度、分均基准、动态权重和评分分支变化等计算明细。基准不可用时只显示 `全服得分 暂不可用`，并继续使用原评分。

## 基础指标

记：

- `clamp01(x) = min(1, max(0, x))`
- `ratio(a, b) = b > 0 ? a / b : 0`

单局评分会计算以下指标：

| 指标 | 公式 | 含义 |
| --- | --- | --- |
| KDA | 游戏内 KDA | 用于高表现保护，不单独作为大权重得分项 |
| 伤害占比 | `个人英雄伤害 / 团队英雄伤害` | 输出份额 |
| 经济占比 | `个人经济 / 团队经济` | 资源占用 |
| 原始伤转 | `伤害占比 / 经济占比` | 拿多少经济打多少输出 |
| 修正伤转 | `伤害占比 / 修正经济占比` | 考虑人头经济后的伤转 |
| 人头占比 | `个人击杀 / 团队击杀` | 击杀份额 |
| 参团率 | `(击杀 + 助攻) / 团队击杀` | 团战参与 |
| 死亡占比 | `个人死亡 / 团队死亡` | 死亡负担 |
| 承伤占比 | `(自我缓和伤害 + 承受到的伤害) / 团队(自我缓和伤害 + 承受到的伤害)` | 承伤份额 |
| 每死承伤 | `(个人承伤 / max(死亡, 1)) / (团队承伤 / max(团队死亡, 1))` | 承伤质量修正 |
| 治疗占比 | `个人治疗 / 团队治疗` | 治疗贡献 |
| 分均控制 | `个人控制次数 / 对局分钟数` | 法师控制评分门槛 |
| 控制占比 | `个人控制次数 / 团队控制次数` | 控制量 |
| 控杀占比 | `个人控制后协助击杀 / 团队控制后协助击杀` | 控制结果 |
| 控制转化 | `个人控制后协助击杀 / 个人控制次数` | 控制质量 |

### 修正伤转

原始伤转的问题是：击杀会带来额外经济。如果一个玩家确实通过高输出拿到人头，经济高不应该完全惩罚他。

因此代码会计算一个修正经济占比：

```text
killQuality = clamp01(1 - max(0, 人头占比 - 伤害占比) / 0.18)
productiveKillShare = min(人头占比, 伤害占比 + 0.04)
killPressure = clamp01((productiveKillShare - 0.18) / 0.18)
killGoldRelief = 0.06 * killPressure * killQuality

修正经济占比 = max(
  经济占比 - killGoldRelief,
  经济占比 * 0.78,
  0.08
)

修正伤转 = 伤害占比 / 修正经济占比
```

简单说：

- 人头占比高但伤害占比低，会被认为偏 K 头，修正很少。
- 人头占比高且伤害占比也高，会适当降低经济分母，减少“打得好所以经济高”带来的伤转惩罚。

### 伤转死亡门控

修正伤转本身仍然是核心指标，但不会直接全额进分。为了避免“无脑送死导致经济占比低，从而刷出高伤转”的情况，代码会把伤转分再经过一层死亡门控：

```text
原始伤转分 = clamp01((修正伤转 - 基础线) / 成长区间)

死亡压力 = clamp01((死亡占比 - 0.20) / 0.12)
死亡保护 = clamp01((伤害占比 - 0.20) / 0.10)
死亡伤害错位风险 = clamp01((死亡占比 - 伤害占比 - 0.02) / 0.12)

送死风险 = max(死亡压力, 死亡伤害错位风险)
保护后送死风险 = 送死风险 * (1 - 死亡保护)

伤转保留比例 = clamp(1 - 保护后送死风险 * 0.65, 0.60, 1)
最终伤转分 = 原始伤转分 * 伤转保留比例
```

简单说：

- 伤害占比越高，说明这次死亡风险有输出结果，死亡扣分越少。
- 伤害占比 20% 以下不保护，20%-30% 线性保护，30% 以上不因死亡扣伤转分。
- 死亡占比高但伤害占比只是中低水平，伤转分会被明显压低。
- 最低仍保留 60% 的伤转分，避免死亡过度否定有效输出。

### 碾压局上下文校准

短时严重碾压局会让队内占比失真：败方正常发挥的玩家可能因为队友表现过低而获得虚高占比，胜方则可能因为五人贡献平均而全部显得普通。评分会在严格门控下，把部分队内占比平滑替换为十人全场占比。

校准只在以下条件同时满足时启用：

1. 对局时长不超过 `16` 分钟。
2. 对局恰好能识别为两支人数相等的队伍。
3. 败方最多只推掉 `1` 座防御塔。败方推掉 `2` 座或更多防御塔时，整局不属于碾压局，K/D、伤害和推塔门控全部停止。
4. 以下三个独立门控至少命中一个：
   - K/D 门控：胜方至少领先 `6` 个人头，并且胜方 `K/D >= 1.30`。败方 K/D 只用于展示，不重复参与门控。
   - 伤害门控：基础要求胜方总伤害达到败方的 `115%`，再按双方坦克和辅助数量动态修正。
   - 推塔门控：败方没有推塔时直接命中；败方恰好推掉 `1` 座塔时，首塔时间超过本局总时长的 `75%` 才命中。该门控只启用碾压局 KDA 评分，不产生推塔强度，也不增加全场数据混合比例。

SGP 摘要中的 `challenges.firstTurretKilledTime` 表示全局一血塔时间，只会出现在拿到一血塔的队伍，不能直接当成双方各自的首塔时间。该字段出现在败方参与者数据中时，它同时也是败方自己的首塔时间，单位为秒。

对于不超过 `16` 分钟、败方恰好推掉 `1` 座塔、但摘要中没有败方首塔时间的对局，后端会按需请求 SGP `/DETAILS` 时间线。在 `BUILDING_KILL` 事件中筛选 `TOWER_BUILDING`，再取首个“被摧毁建筑属于胜方”的时间戳，换算为败方自己的首塔时间。`BUILDING_KILL.teamId` 表示被摧毁建筑所属队伍，不是推塔方。详情不可用时保持缺失，不启用推塔门控，也不给 KDA 借权；败方 `0` 塔不需要首塔字段，败方达到 `2` 塔则直接排除碾压局，也不会额外请求时间线。

```text
经济差 = abs(双方经济差) / 双方总经济
胜方K/D = 胜方击杀 / max(胜方死亡, 1)
败方K/D = 败方击杀 / max(败方死亡, 1)

战斗差 = (胜方K/D - 败方K/D) / (胜方K/D + 败方K/D)
胜方伤害倍率 = 胜方伤害 / 败方伤害
动态伤害门槛 =
  1.15
  - (胜方坦克数 - 败方坦克数) * 0.10
  - (胜方辅助数 - 败方辅助数) * 0.05
伤害门控 = 胜方伤害倍率 >= 动态伤害门槛
胜方伤害差 = 胜方伤害倍率 - 1

时长系数 = 对局 <= 12分钟 ? 1 : lerp(1, 10/35, (对局分钟 - 12) / 4)
K/D强度 = K/D门控命中 ? lerp(0.18, 1, smoothstep((胜方K/D - 1.30) / 1.70)) : 0
伤害强度 = 伤害门控命中
  ? lerp(0.18, 1, smoothstep((胜方伤害倍率 - 动态伤害门槛) / 0.20))
  : 0
主强度 = max(K/D强度, 伤害强度)
经济放大 = lerp(0.82, 1.00, smoothstep((胜方经济差 - 0.03) / 0.15))
碾压强度 = 时长系数 * 主强度 * 经济放大
全场混合权重 = 碾压强度 * 0.65
```

因此：

- 超过 `16` 分钟完全不校准。
- 败方推掉 `2` 座或更多防御塔时完全不校准。
- K/D、伤害差和推塔时间门控都未命中时完全不校准。
- K/D 与伤害门控同时命中时取强度更高的一项，不把两项相加，避免校准过度。
- 胜方每比败方多 `1` 个坦克，伤害倍率门槛降低 `10` 个百分点；少 `1` 个则提高 `10` 个百分点。
- 胜方每比败方多 `1` 个辅助，伤害倍率门槛降低 `5` 个百分点；少 `1` 个则提高 `5` 个百分点。
- 例如胜方 `3` 坦克、败方 `1` 坦克时，门槛为 `95%`；胜方 `0` 坦克、败方 `2` 坦克时，门槛为 `135%`。
- 例如胜方 `1` 辅助、败方 `0` 辅助时，门槛为 `110%`；胜方 `0` 辅助、败方 `1` 辅助时，门槛为 `120%`。
- 仅命中推塔门控时，碾压强度与全场混合比例均为 `0`，只从伤害/伤转分池中划出败方推塔进度对应的 KDA 权重。
- 经济差只把强度从 `82%` 平滑放大到 `100%`，不再决定是否触发。
- 最严重的碾压局也只混入最多 `65%` 的全场数据，至少保留 `35%` 原队内评价。

全场占比会按队伍人数标准化，使普通五人队伍的平均值仍为 `20%`：

```text
全场标准化占比 = 个人数值 / 十人总值 * (全场人数 / 本队人数)

有效占比 =
  原队内占比 * (1 - 全场混合权重)
  + 全场标准化占比 * 全场混合权重
```

第一版只校准最容易在碾压局中失真的指标：

- 伤害占比
- 经济占比
- 人头占比
- 死亡占比
- 参团率
- 基于有效伤害、经济、人头重新计算的修正伤转

承伤、治疗和控制仍使用原始队内占比。界面与玩家画像也继续展示原始数据，只有本局评分和标签使用有效指标。

#### 碾压局 KDA 权重

碾压局触发后，输出、法师和战士类公式允许从原本的伤害占比与伤转分池中划出一部分给 KDA；坦克和辅助不参与这项重分配。

```text
败方首塔进度 = 败方首塔时间 / 对局总时长

最大KDA权重 =
  败方推塔数为0：35分
  败方推塔数为1：35 × clamp((败方首塔进度 - 75%) / 25%, 0, 1)
  败方推塔数达到2：不属于碾压局

KDA质量 = clamp((KDA - 1) / 4, 0, 1)
KDA得分 = 实际KDA权重 * KDA质量
```

败方首塔发生在对局 `75%` 进度时，最大 KDA 权重为 `0`；发生在 `87.5%` 时为 `17.5` 分；直到对局结束才推掉首塔时为 `35` 分；败方一座塔都没推也为 `35` 分。例如 `16` 分钟对局中败方在 `12` 分钟推掉首塔，首塔进度正好是 `75%`，最大 KDA 权重为 `0`。

即 KDA `<= 1` 时该项为 `0`，KDA `3` 获得一半实际权重，KDA `>= 5` 获得全部实际权重。KDA 权重会优先从动态战斗分池中预留，剩余分数再分配给伤害、伤转、承伤或控制，因此不会凭空扩大总分上限。

胜方不会固定使用最大 KDA 权重，而是按“最终总分最高”选择评分方案：

1. 先把完全不启用碾压校准的原始评分作为基线候选。
2. 再使用碾压校准后的有效指标，在 `0` 到败方推塔进度允许的最大 KDA 权重之间按 `0.5` 分步长计算候选。
3. 额外计算精确的最大 KDA 权重端点，避免首塔进度线性变化产生的小数上限被遗漏。
4. 选择最终得分最高的候选；如果分数相同，优先保留原始算法或更低的 KDA 权重。

因此胜方可能完全不启用碾压算法，也可能只使用部分 KDA 权重，或者使用全部 KDA 权重。启用碾压算法不会让胜方玩家低于自己的原始评分。这样可以兼容两类表现：高 KDA 玩家可以从短时碾压中获得合理识别，伤害占比和伤转更优秀但 KDA 一般的玩家也不会因为强制挪走过多权重而掉分。

败方不参与这项“取最高分”保护，仍固定使用败方推塔进度允许的最大 KDA 权重，再应用下方的败方抵抗保护。

#### 败方抵抗保护

碾压局中，如果败方某位玩家仍然打出了至少 `27%` 的队内伤害占比和 `1.20` 的原始伤转，会平滑减免其负向碾压校准。该保护只减少扣分，不会额外加分。

```text
伤害进度 = clamp((伤害占比 - 0.27) / 0.08, 0, 1)
伤转进度 = clamp((伤转 - 1.20) / 0.25, 0, 1)
抵抗保护 = sqrt(伤害进度 * 伤转进度)

保护后负向校准 = 原负向校准 * (1 - 抵抗保护)
```

伤害占比 `27%`、伤转 `1.20` 是保护起点；两项继续提高时扣分逐步减少。达到伤害占比 `35%` 且伤转 `1.45` 时保护为 `100%`，该玩家的负向碾压校准归零，但原始评分不变。

胜负结果项最多为 `±3` 分：胜方必须先有足够个人贡献才获得加分；败方如果有效伤害或环境评分足够高，会减免失败修正。最后使用随碾压强度增长的动态保险：

```text
普通校准变化上限 = 碾压强度 * 25
校准变化上限 =
  坦克或辅助：普通校准变化上限
  其他定位：max(普通校准变化上限, min(实际KDA权重, 25))
最终校准变化 = clamp(环境评分 - 原始评分, -校准变化上限, +校准变化上限)
最终得分 = 原始评分 + 最终校准变化
```

败方额外有一条单向上限：

```text
败方最终得分 = min(原始得分, 原始得分 + 负向校准)
```

因此败方的碾压算法只能扣分或保持原分，不能因为 KDA 借权、环境评分或结果修正而超过原始得分。正常局评分完全不变；坦克和辅助仍完全按碾压强度决定变化上限。其他定位为了让 KDA 重分配不被低强度上限压平，会使用实际选择的 KDA 权重参与下限保护，但最终任何定位单局最多仍只改变 `25` 分。胜方额外执行候选最大化，最终得分不会低于原始评分；败方最佳玩家仍然可以高于胜方最差玩家。

### 控制质量

控制不直接用控制时长，因为减速等廉价控制会污染这个指标。当前使用控制相关数据，并把分均控制纳入质量：

```text
if 分均控制 <= 1:
  控制质量 = 0
else:
  控制占比分 = clamp01(控制占比 / 0.30)
  控制转化分 = clamp01(控制转化 / 0.30)
  分均控制分 = clamp01((分均控制 - 1) / 2)
  分均门控 = 0.40 + 分均控制分 * 0.60
  控制基础盘 = 控制转化分 * 0.55 + 控制占比分 * 0.45

控制质量 =
  clamp01(控制基础盘 * 分均门控 * 0.70 + 分均控制分 * 0.30)
```

也就是说，分均控制必须先超过 `1` 才会进入控制评分。分均控制会作为总阀门压低低频高占比局，同时也会单独给高频控制补分：控制转化和控制占比很高但分均控制低时，控制质量会被压低；控制转化和控制占比一般但分均控制很多时，控制质量也会被抬高。

### 法师控制质量

法师分支不使用上面的通用控制质量，而是使用更直接的法师控制质量。它先看绝对控制频率：

```text
分均控制 = 个人控制次数 / 对局分钟数

if 分均控制 <= 1:
  法师控制质量 = 0
else:
  法师控制质量 = 控制质量
```

也就是说，法师想吃控制分，必须先有超过 `1` 的分均控制；过了门槛后，同时看团队控制占比、控杀转化率和分均控制频率。

## 定位判断

定位判断位于 `roleClassifier.ts`。

基础定位有 6 类：

- `adc`
- `mage`
- `assassin`
- `fighter`
- `tank`
- `support`

最终显示定位还会派生出：

- `bruiser`：半肉战士
- `pureAssassin`：纯刺客
- `fighterAssassin`：战士刺客
- `utilityCarry`：功能输出
- `unknown`：输出

### 英雄定位

英雄资源中每个英雄有 `roles`。第一个英雄标签权重更高：

```text
主标签权重 = 1.25
副标签权重 = 0.85
```

随后归一化成英雄定位向量。

### 装备定位

装备定位来自三部分：

1. 装备图标路径，比如 `marksman`、`mage`、`assassin`、`fighter`、`tank`、`support`。
2. 装备分类和描述，比如暴击、攻速、穿甲、法强、生命值、护甲、治疗护盾强度等。
3. 手写装备修正表 `ITEM_FIXES`，用于修正游戏资源里分类不够准确的装备。

装备权重按价格计算：

```text
price <= 0      -> 0
price < 900     -> price * 0.20
price < 1800    -> price * 0.45
price >= 1800   -> min(price, 3600)
```

这样小件、鞋子、消耗品不会过度影响定位，成装会成为主要证据。

### 英雄和装备的合并

装备权重越高、装备倾向越集中，装备越能决定本局定位。

```text
itemDominance = 装备定位向量中的最大值

if itemGold >= 4500:
  itemRatio = itemDominance >= 0.75 ? 0.78 : 0.65
else if itemGold >= 2200:
  if itemDominance >= 0.80: itemRatio = 0.72
  else if itemDominance >= 0.65: itemRatio = 0.62
  else itemRatio = 0.52
else:
  itemRatio = itemDominance >= 0.85 ? 0.55 : 0.40

championRatio = 1 - itemRatio
最终定位向量 = 装备向量 * itemRatio + 英雄向量 * championRatio
```

如果英雄资源里的主定位和次定位都不是 `marksman`，装备侧的 ADC 倾向不会参与最终定位计算。也就是说，非 ADC 英雄即使出了暴击、攻速等 ADC 装备，也不会被最终判成 ADC。若过滤后装备侧没有有效定位证据，则本局定位回到英雄定位向量主导。

### 最终定位规则

按顺序判断：

| 条件 | 定位 |
| --- | --- |
| `fighter >= 0.30 && tank >= 0.24` | 半肉战士 |
| `fighter >= 0.28 && assassin >= 0.24` | 战士刺客 |
| `assassin >= 0.46 && tank < 0.16 && fighter < 0.26` | 纯刺客 |
| `support >= 0.38 && max(adc, mage, assassin, fighter) < 0.42` | 辅助 |
| `support >= 0.28 && max(adc, mage) >= 0.28` | 功能输出 |
| `tank >= 0.42 && fighter < 0.24` | 坦克 |
| 最高权重定位 `>= 0.22` | 对应定位 |
| 其他 | 输出 |

## 前排分支

前排分支适用于坦克。

| 子分 | 公式 | 满分 |
| --- | --- | --- |
| 承伤质量 | `30 * 门控承伤质量(0.30, 1.10)` | 30 |
| 有效伤害/控制共享池 | 伤害分和控制质量按表现共享 30 分 | 30 |
| 参团 | `15 * clamp01((参团率 - 0.42) / 0.38)` | 15 |
| 死亡控制 | `10 * 高表现保护后的生存分(0.28, 0.22)` | 10 |
| 定位匹配 | `clamp01((坦克权重 + 战士权重) / 0.65)` | 1 |
| 效率 | `9 * 伤转死亡门控(0.65, 0.55)`，修正伤转 `1.20` 时满分 | 9 |
| 治疗 | `5 * clamp01(治疗占比 / 0.25)` | 5 |

共享池内部：

```text
伤害分 = clamp01(伤害占比 / 0.24)
控制分 = 控制质量
伤害权重 = 30 * 伤害分 / (伤害分 + 控制分)
控制权重 = 30 - 伤害权重
有效伤害子分 = 伤害权重 * 伤害分
控制子分 = 控制权重 * 控制分
```

如果没有伤害和控制表现，则共享池为 `0`。

前排不会完全忽略输出。伤害占比和修正伤转仍然会给分，只是承伤质量占比最高。

## 动态承伤与控制权重

输出、法师和战士的承伤、控制权重不是固定的。它们可以为 0，也可以从“伤害和伤转分池”里借权重，但必须满足“借过去后更赚”的条件。

承伤借权重必须满足三个条件：

1. 承伤质量分高于非承伤战斗表现。
2. 承伤占比达到启动线。
3. 每死承伤达到启动线。

基础分：

```text
伤害分 = clamp01(伤害占比 / 伤害目标)
伤转分 = 伤转死亡门控(伤转基础线, 伤转成长区间)

承伤质量 =
  clamp01(承伤占比 / 承伤目标占比) * 0.65
  + clamp01((每死承伤 - 0.55) / (承伤目标每死 - 0.55)) * 0.35

比较用伤害比例 =
  伤害权重比例 + 伤害固定偏移 / 战斗分池

非承伤战斗分 =
  伤害分 * 比较用伤害比例
  + 伤转分 * (1 - 比较用伤害比例)

承伤优势 = 承伤质量 - 非承伤战斗分
```

只有 `承伤优势 > 0` 时才会借权重：

```text
承伤占比门槛 = clamp01((承伤占比 - 承伤占比启动线) / 承伤占比成长区间)
每死承伤门槛 = clamp01((每死承伤 - 每死承伤启动线) / 每死承伤成长区间)
优势门槛 = clamp01(承伤优势 / 承伤优势区间)

boost = 承伤占比门槛 * 每死承伤门槛 * 优势门槛
承伤权重 = 承伤最高可借权重 * boost
```

控制借权重只对特定英雄开放：

| 条件 | 控制最高可借权重 |
| --- | --- |
| 法师分支 | 30 |
| 英雄定位里辅助最高、其他定位第二，且最终不是纯辅助 | 30 |
| 其他英雄 | 0 |

法师分支使用“法师控制质量”；其他分支如果能吃到控制动态分，则使用通用控制质量。

控制权重同样要求控制质量高于原本伤害/伤转组合：

```text
控制优势 = 控制质量 - 非承伤战斗分

if 控制优势 > 0:
  控制质量门槛 = clamp01(控制质量)
  控制优势门槛 = clamp01(控制优势 / 0.45)
  控制权重 = 控制最高可借权重 * 控制质量门槛 * 控制优势门槛
else:
  控制权重 = 0
```

剩余权重继续分给伤害和伤转：

```text
基础权重 = 战斗分池 - 承伤权重 - 控制权重
伤害固定偏移 = 输出/法师为 3，其他定位为 0
伤害权重 = 基础权重 * 伤害权重比例 + 伤害固定偏移
伤转权重 = 基础权重 - 伤害权重

动态伤害子分 = 伤害权重 * 伤害分
动态伤转子分 = 伤转权重 * 伤转分
动态承伤子分 = 承伤权重 * 承伤质量
动态控制子分 = 控制权重 * 控制质量
```

这个设计的目的是：

- 输出位不会因为刷承伤获得高分。
- 战士承伤高且每死承伤质量好时，可以获得额外收益。
- 法师分支可以因为高质量专属控制获得收益；辅助底子的功能输出使用通用控制质量获得收益。
- 承伤和控制收益来自伤害/伤转分池，不会凭空增加总权重。

## 人头质量

人头质量用于区分“确实在 C”和“只会 K 头”。

```text
K头差 = max(0, 人头占比 - 伤害占比)
KDA保护 = clamp01((KDA - 3) / 4)
伤害保护 = clamp01((伤害占比 - 0.24) / 0.12)
高表现保护 = KDA保护 * 伤害保护
修正K头差 = K头差 * (1 - 高表现保护 * 0.65)

人头质量 = clamp01(1 - 修正K头差 / 0.18)
```

人头占比明显高于伤害占比时，人头质量下降；但如果 KDA 和伤害占比同时很高，会认为这是碾压局或核心输出局，降低 K 头惩罚。

## 高表现保护后的生存分

死亡占比会被伤害占比修正：

```text
原始死亡惩罚 = clamp01((死亡占比 - 起扣线) / 成长区间)
死亡保护 = clamp01((伤害占比 - 0.20) / 0.10)
保护后死亡惩罚 = 原始死亡惩罚 * (1 - 死亡保护)

生存分 = 1 - 保护后死亡惩罚
```

这个修正用于输出、战士、前排、辅助的死亡控制或生存子分。它不会让低伤害保命局变成高分，只会保护真实承担高伤害占比的局。

## 前排承伤质量

前排使用更严格的门控承伤质量：

```text
承伤占比分 = clamp01(承伤占比 / 目标承伤占比)
每死承伤分 = clamp01((每死承伤 - 0.55) / (目标每死承伤 - 0.55))
门控承伤占比分 = 承伤占比分 * (0.35 + 每死承伤分 * 0.65)

门控承伤质量 = 门控承伤占比分 * 0.70 + 每死承伤分 * 0.30
```

也就是说，坦克无脑送死刷承伤不会稳定拿满分；每死承伤越低，承伤占比的价值越低。

## 娱乐称号池

`tag` 是评分公式里的单个行为标签；战绩卡片和本机接口另外提供娱乐称号：

- `score.title`：本局当前随机展示的一个称号。
- `score.titles`：本局全部命中的称号，便于悬浮窗查看完整结果。
- `score.titleDetails`：每个称号的类别、层级和简短命中理由。
- `score.factTags`：伤害第一、评分队内第一等客观事实，不和调侃称号混在一起。

称号不是互斥等级。一个对局可以同时命中“悲情英雄”“本质高手”和“木已成舟”等多个称号，展示时按层级加权随机抽取一个；刷新接口或重新打开软件会重新抽取，但同一响应内保持稳定。

称号阈值以普通玩家为主要校准对象，而不是以顶尖玩家的极端表现为门槛。当前三组 100 局海克斯大乱斗样本的量级为：普通玩家平均约 `65` 分、普通偏上约 `71` 分、明显高水平玩家约 `89` 分。普通样本中队友平均分不超过 `45` 只有极少数，评分不超过 `20` 基本只代表挂机、残缺数据或极端局，因此这些条件只保留给少数调侃称号，不作为常规夸奖称号的入口。普通玩家在正常发挥、赢下但不抢镜、败方尽力或某一职责突出时，都应能命中至少一个称号。

辅助称号还会区分治疗和护盾职责：治疗称号必须有可观测的队友治疗和对应英雄全服基准表现，护盾称号则使用队友护盾基准；不能因为保护总量较高，就把纯护盾局误称为治疗局。

### 大样本时间权重

数据统计和历史能力读取通常会包含 `100-500` 场甚至更多对局。单纯平均会让很久以前的表现过度稀释近期状态，因此大样本画像按实际参与统计的有效场次 `N` 计算混合权重。这里的 `N` 是模式、日期和时长过滤后的实际场次，不是下拉框的请求上限。

按对局时间从新到旧编号 `i = 0, 1, 2...`：

```text
近期原始权重 = 2 ^ (-i / 20)
近期归一化权重 r(i) = 近期原始权重 / Σ近期原始权重

场次混合比例 λ(N) = clamp(0.30 + 0.10 * log2(N / 50), 0.30, 0.55)
```

因此 `N = 100` 时近期部分约占 `40%`，`N = 200` 时约占 `50%`，`N >= 400` 时最多占 `55%`。其余权重仍均匀保留给全样本，避免短期连胜或连败完全覆盖长期能力。

真实时间只作为“近期状态是否仍有效”的门控，而不是直接替代对局序号：

```text
距最近有效对局 <= 7 天：活跃度 F = 1
7-30 天：F 从 1 平滑下降到 0
距最近有效对局 >= 30 天：F = 0

最终近期比例 = λ(N) * F
单局最终权重 w(i) = (1 - 最终近期比例) / N + 最终近期比例 * r(i)
综合分 = Σ(单局得分 * w(i))
```

这意味着一个月未对局的玩家不会把旧对局误当成“当前状态”：其综合分会退回全样本均值。实时战绩卡片显式关闭该规则，因为它本身只统计较短的近期样本。

## 画像标签

玩家画像会先加入一个聚合 tag，然后根据平均指标追加多个标签，最多保留 10 个。正面画像标签同样要求综合分 `>= 65`。

### 聚合 tag

聚合评价不是简单找所有标签里出现最多的，而是先找分段：

| 分段 | 条件 |
| --- | --- |
| 高分段 | `>= 80` |
| 正常段 | `60-79` |
| 低分段 | `40-59` |
| 战犯段 | `< 40` |

规则：

1. 先按上述最终权重统计每个分段的权重。
2. `<40` 战犯段只有占比 `>= 30%` 时才有资格成为主分段。
3. 在有资格的分段里，选择权重最高的分段。
4. 在该分段内部，选择加权次数最高的单局标签作为画像主标签。

这样可以避免“少量大坑比局”压过大量高分局，也避免高分局标签过于分散时被低分标签轻易盖住。

注意：这里的 `<40` 是“画像主标签分段保护”的战犯段；画像面板里的战犯率统计口径是 `得分 < 60`，两者不是同一个概念。

| `综合分 >= 80 && 输出能力线占比 >= 0.65 && 平均伤害占比 >= 0.24` | 输出机器 |
| `综合分 >= 65 && 输出能力线占比 >= 0.65 && 平均伤害占比 >= 0.24` | 稳定火力 |
| 有主定位 | `常用{定位}` |

## 单英雄画像

单英雄画像由 `buildChampionProfiles` 生成：

1. 按英雄 ID 分组。
2. 对每个英雄的所有对局重新计算评分。
3. 统计该英雄的主定位、画像标签、高光率、战犯率、平均伤害占比、平均伤转、平均承伤占比、平均治疗占比。

其中单英雄战犯率同样按 `得分 < 60` 统计。

单英雄表格里的“标签”使用分段聚合，而不是根据平均数据重新生成：

1. 先按该英雄的所有对局分成 `>=80`、`60-79`、`40-59`、`<40` 四个分段，并按时间权重累计各分段。
2. `<40` 分段只有占比达到 `30%` 时，才有资格成为主分段。
3. 选择权重最高的主分段。
4. 在这个主分段里，选择加权次数最高的单局 tag。

例如某个英雄 `80` 分以上的对局最多，就只在这些 `80` 分以上的对局里统计 tag 次数，出现最多的 tag 就是单英雄表格里的标签。

单英雄 tag 的颜色同样跟随主分段，而不是根据 tag 文本判断：`>=80` 金色，`60-79` 绿色，`40-59` 蓝色，`<40` 红色。

单英雄评分会保留中位数和主分段的稳定性；当该英雄至少有 `10` 场有效对局且玩家仍处于活跃期时，额外加入 `20%` 的近期衰减分：

```text
活跃且样本 >= 10：
单英雄评分 =
  全样本平均分 * 0.40
  + 中位数 * 0.25
  + 主分段平均分 * 0.15
  + 该英雄近期衰减分 * 0.20

样本不足或最近一局超过 30 天：
单英雄评分 =
  全样本平均分 * 0.60
  + 中位数 * 0.25
  + 主分段平均分 * 0.15
```

其中“主分段”的选择和玩家画像一致：`>=80`、`60-79`、`40-59`、`<40`，且 `<40` 分段只有占比达到 `30%` 时才有资格成为主分段。

## 当前设计倾向

当前评分系统有几个明确倾向：

1. 输出位以伤害占比和修正伤转为核心，不再给 KDA 独立大权重。
2. 人头占比必须结合伤害占比看，避免“只会 K 头”被高估。
3. 承伤必须结合每死承伤看，避免无脑送死刷承伤。
4. KDA 和伤害占比同时高时，会降低死亡占比和人头占比在碾压局里被放大的惩罚。
5. 输出、法师和战士的承伤、控制权重是动态的，只有优于伤害/伤转表现时才会借权重。
6. 英雄主次定位都不是 ADC 时，不允许仅靠装备被判成 ADC。
7. 坦克、辅助有独立公式，但仍保留一定输出、效率或控制权重。
8. 玩家画像先按分段聚合，再找分段内主标签，避免少量低分局轻易覆盖大量高分局。

## 可调参数入口

常见调整点：

- `scoring.ts`
  - 各分支权重。
  - 动态承伤、控制分池参数。
  - KDA/伤害占比高表现保护参数。
  - 单局标签阈值。
  - 分数色阶。
- `roleClassifier.ts`
  - 装备修正表 `ITEM_FIXES`。
  - 装备和英雄定位合并比例。
  - 非 ADC 英雄的 ADC 装备倾向过滤规则。
  - 最终定位判定阈值。
- `playerProfile.ts`
  - 主分段保护阈值 `DISASTER_BAND_DOMINANT_RATE`。
  - 战犯率分数线 `DISASTER_RATE_SCORE_LIMIT`。
  - 玩家画像标签阈值。
  - 单英雄加权平均公式。
